Bachelor thesis, written during my internship at Advantech in Tokyo. The question: is a Neural Processing Unit actually worth it on a drone-sized board?

Object Detection on an Embedded Drone Companion Computer

Comparing Inference Hardware Approaches

Howest University of Applied Sciences Advantech Co., Ltd., Tokyo 2025 / 2026

One YOLOv8 detector, deployed twice on the same Advantech ASR-D501 board: once on the ARM CPU, once offloaded to the Qualcomm QCS6490's Hexagon NPU. Same model, same camera, same drone, same motor-control loop. Only the silicon doing the inference changes.

The NPU build runs YOLOv8n at 110.3 frames per second while drawing roughly ten percent less total board power. The thesis documents the whole deployment path: PyTorch through ONNX to INT8 TFLite, moving the vendor's Yocto pipeline onto Ubuntu, handling camera input across sensor types, plus a benchmark sweep over eight YOLO variants to characterise how NPU throughput scales with model size.

// what the numbers say

Is a Neural Processing Unit worth it for object detection on a drone?

On this hardware, decisively yes. The same YOLOv8n model runs at 110.3 FPS on the Qualcomm QCS6490's Hexagon NPU versus 1.3 FPS on the same board's ARM CPU, about 85× the throughput, while the board draws roughly 10% less total power. On the CPU the detector cannot keep up with a live camera feed at all, so a drone cannot react to what it sees. The NPU is what makes onboard detection a real-time control input rather than a recording.

How fast is YOLO on the Qualcomm QCS6490 NPU?

Measured on an Advantech ASR-D501, INT8-quantized, frames per second: YOLOv8n 110.3, YOLOv8s 89.9, YOLOv8m 42.6, YOLOv8l 30.8, YOLOv8x 20.3. YOLOv11 tracks closely: YOLOv11n 103.5, YOLOv11s 82.6, YOLOv11m 40.2. Throughput falls off sharply above the small variants, so the nano and small models are the practical choices for a flight-control loop.

Can a Raspberry Pi 5 run YOLOv8 object detection in real time?

Not on the CPU. In the same benchmark a Raspberry Pi 5 reached 1.1 FPS with YOLOv8n, close to the ASR-D501's own CPU result of 1.3 FPS, and roughly a hundred times slower than that board's NPU. Real-time onboard detection needs a dedicated accelerator; general-purpose ARM cores are not enough at this model size.

What does it take to deploy a YOLO model on the Hexagon NPU under Ubuntu?

The conversion path is PyTorch → ONNX → INT8 TensorFlow Lite. The harder part is everything around it: the vendor ships a Yocto-based GStreamer pipeline that has to be adapted to run on Ubuntu, and camera input handling differs by sensor type. Quantizing the model was the quick step. The pipeline and camera plumbing took most of the work.

Autonomous Drone YOLO Object Tracking

PythonAdvantech ASR-D501Qualcomm QCS6490YOLOv8ROS2MAVLinkRTAB-Map

Built a fully autonomous drone system for Advantech's Japan IT Week demo. Assembled the hardware from scratch, configured the Pixhawk flight controller, and installed ROS 2 with MAVROS on the Advantech ASR-D501 companion computer. Wrote a Python pipeline that runs YOLO for real-time object detection, locks onto a target, tracks its screen position, and sends yaw commands to the motors so the drone rotates to follow the object while hovering at a fixed altitude.

Also developed a second variant running a quantized YOLO model on the board's Qualcomm Hexagon Neural Processing Unit, reaching 110.3 FPS against 1.3 FPS on the same board's CPU. That comparison became my bachelor thesis.

In parallel, built a real-time SLAM pipeline with RTAB-Map for 3D environment reconstruction, laying the groundwork for fully spatially-aware drone navigation.

02software × tooling

GeoMeta Map Geography Trainer

JavaScriptLeafletGeoJSONMarkdownSelf-hosted

A study tool for GeoGuessr. Every country on the world map is clickable, and each one holds your own notes on what identifies it: bollards, road markings, license plates, utility poles, script, the shape of a stop sign. Notes are written in Markdown, screenshots paste straight in, and each one is filed under a category and tagged.

Clicking a country opens its dossier: driving side, top-level domain, phone prefix, currency, language and writing system, plus every note recorded for it. Countries are shaded by whether they drive on the left or right and outlined when they have notes, so the map itself shows what has been covered and what has not.

The part that makes it useful for actual learning is the inverse view. Switch to browse by category or tag and the map re-colours to show every country sharing that clue at once. Pick "yellow plates" and Colombia, Israel, the Netherlands and Uganda light up together. That turns a pile of individual notes into the pattern you are really trying to memorise.

03software × ai

EraseAll Object Removal

PythonSegmentationInpaintingCPU-onlyOffline

An image editor built around one job: taking things out of photographs and reconstructing what was behind them. The constraint I set myself was that it had to run on an ordinary laptop CPU: no dedicated GPU, no cloud service, no uploading someone's holiday photos to a server.

Several selection modes cover different situations. Select people detects everyone in the frame automatically and labels them, so you tick which ones stay and remove the rest in a single click. Smart and Object snap to edges for quick selections, Raw is a plain brush for full manual control, and there is a clone stamp for touching up whatever the fill gets wrong.

After a removal the tool proposes several fill variants and you keep the one that reads best, rather than being stuck with a single guess. Clearing an entire tourist crowd out of a temple courtyard takes about ten seconds of selection work.

04robotics × ai

Autonomous Navigation Behavior Tree

ROS2C++Behavior TreesNav2

Engineered a custom ROS 2 Behavior Tree for the ROSMASTER X3 to handle autonomous navigation in tight, dynamic environments. Default navigation stacks try to aggressively replan around obstacles, which creates collision risks in spaces like warehouse aisles or restaurant dining areas.

Designed a "stop-and-wait" pipeline instead: when the robot detects a dynamic obstacle (like a person), it halts along its trajectory, waits for the path to clear, then resumes its original route. This guarantees predictable, collision-free operation and prevents the robot from dangerously swerving into walls or furniture.

05systems × security

BIOS Flash Utility

CPOSIXLinux

Built a compiled, systems-level C utility for Advantech that streamlines BIOS flashing. The tool scans the local directory for .rom files and generates an interactive menu for the operator. Includes strict memory-bounds checking to prevent buffer overflows, an input allowlist to reject suspicious filenames, and uses native POSIX process management (fork() and execvp()) to execute the flash tool directly via the kernel, eliminating any risk of shell-based command injection.
